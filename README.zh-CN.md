# agent-desktop 中文说明

## 项目概述

`agent-desktop` 是一个面向 AI 智能体的桌面自动化与计算机使用工具。它不直接生成“智能体思维”，而是让智能体能够通过系统原生的辅助功能（Accessibility）读取桌面应用界面，并在必要时对目标控件执行点击、输入、滚动、拖拽、快捷键等操作。

项目的核心目标是：

- 让 AI 能“看见”桌面应用的界面结构
- 让 AI 能通过稳定的引用（ref）定位界面元素
- 让 AI 能执行真实的桌面操作，而不是仅仅模拟网页交互
- 让这套能力同时覆盖 macOS、Windows 和 Linux

项目本体是 Rust 编写的 CLI，同时提供 MCP（Model Context Protocol）服务和 C ABI（FFI）接口，以便集成到不同的自动化链路中。

## 这个项目能解决什么问题

它适合实现以下场景：

- 桌面软件上的控件识别：按钮、输入框、表格、菜单、弹窗等
- 自动化填写表单：例如把数据录入到本地应用或企业内部系统
- 自动点击和导航：打开应用、切换窗口、点击菜单、确认对话框
- 检查界面状态：某个元素是否存在、是否可用、是否已勾选、某文本是否出现
- 观察和等待 UI 变化：等待加载完成、等待弹窗出现、等待页面状态变化
- 让智能体基于桌面应用能力完成“计算机使用”任务，而不是仅处理网页或 API

它不是纯视觉识别工具，也不是一个通用的 GUI 回归测试框架；它更偏向“结构化桌面操作与观察”。

## 它的核心工作方式

这个项目的设计思路可以概括为：

1. 读取目标应用的 Accessibility Tree / UI 元素树
2. 对元素进行结构化分析和索引
3. 为每个重要元素生成一个引用（ref）
4. 调用方使用这些 ref 查询元素状态或执行动作
5. 再重新读取界面，确认操作是否生效

这套流程符合很多 AI 自动化场景：

- 先观察
- 再定位
- 再操作
- 再验证

而不是“盲目发送点击事件”这种低可靠性的方式。

### 使用例子

读取应用界面：

```bash
agent-desktop snapshot --app Finder -i
```

此命令会返回 JSON 结构，其中包含应用层级结构和各元素的引用（ref）。

操作元素：

```bash
agent-desktop click '@s8f3k2p9:e8'
```

重新观察验证：

```bash
agent-desktop snapshot --app Finder -i
```

## 系统支持情况

项目支持以下平台：

- macOS：通过 Accessibility API
- Windows：通过 UI Automation
- Linux：通过 AT-SPI

不同平台的能力和限制不完全相同，所以工具在各平台上需要遵守各自的权限、可见性和安全约束。

## 它能不能“查找界面问题”

可以做“结构化界面检查”，例如：

- 某按钮是否存在
- 某输入框是否可编辑
- 某菜单项是否可见
- 某状态是否已勾选
- 某弹窗是否出现
- 某元素是否在某条件下变为可操作状态

但它不等于“万能页面视觉诊断工具”。如果一个界面元素没有向操作系统暴露正确的辅助功能信息，或者它是完全自定义绘制的 UI，那么工具可能无法稳定识别和操作它。对于纯视觉问题（例如颜色错误、布局偏移、字体问题），这类工具通常不是首选方案。

## 它能不能自动化操作软件

可以，且这是这个项目最核心的用途之一。它具备：

- 点击、双击、右键点击
- 输入文本、清空内容、设置值
- 选择、勾选、展开/收起
- 拖拽、滚动、鼠标事件、键盘事件
- 启动/关闭应用
- 管理窗口和显示器
- 复制/粘贴剪贴板数据
- 等待界面变化

换句话说，它可以作为桌面端 AI 自动化的底层能力层。它本身不负责决定“业务流程”，但可以提供稳定的界面观察和操作能力给更高层的智能体使用。

## 需要一直保持开启吗？能后台运行吗？

通常不需要“常驻”运行：

- CLI 模式下，每次运行一条命令，调用结束即退出
- MCP 模式下，可以作为后台服务持续运行，以供智能体持续调用
- 目标应用通常仍然需要处于运行状态，工具才能访问它的界面

因此，这个项目更适合作为“桌面控制引擎”，而不是必须全天候后台挂起的系统服务。它支持无头操作，但仍然依赖桌面会话、系统权限和目标应用的正常运行。

## 适用场景总结

适合：

- 代理式桌面自动化
- 本地 GUI 应用控制
- AI 通过桌面界面完成任务
- 自动化脚本与智能体接入
- 桌面界面状态验证

不太适合：

- 纯视觉 UI 误差检测
- 需要对所有每个像素进行精细图像分析的场景
- 没有可访问性支持的自定义渲染 UI

## 说明

这个项目更像“桌面应用的控制层”和“AI 能用的电脑接口”，而不是传统意义上的桌面自动化脚本框架。它的价值在于：一方面让 AI 能观察和操作真实的桌面软件，另一方面通过安全的 JSON 结果、ref 机制和错误处理，支撑稳定且可审计的自动化流程。

如果你正在考虑把它用于智能体桌面自动化，最重要的不是“看它能不能点一下按钮”，而是要先确认：

- 目标应用是否公开了辅助功能结构
- 目标平台是否已被支持
- 用户权限是否已授予
- 智能体是否会在必要时重新观察和校验

只有在这些前提下，它才能真正稳定工作。

## 一句话总结

`agent-desktop` 是一个让 AI 能观察并操作桌面应用的 Rust 项目，适合做“计算机使用”自动化；它可以做界面状态查询和桌面操作，但更擅长结构化、可验证的桌面自动化，而不是纯视觉缺陷识别。
